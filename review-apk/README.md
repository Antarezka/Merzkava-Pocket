# Merzkava Pocket — Android Shell

Android shell implementation for the approved Pocket launch flow and homepage frame.

## Launch and access

- Cold start always opens the independent Login Gate.
- Player login accepts an exact character name from the currently pinned Merzkava Universe `players.md`. The native adapter resolves the active pinned SHA, verifies the registry, and stores the verified identity/profile reference locally for suggestions and later use. A local cache never bypasses the live registry check.
- Developer login uses the same PBKDF2-SHA-256 verifier contract as Merzkava APK (600,000 iterations). The password is not embedded or stored in plaintext. Optional Remember Me encrypts the credential pair with Android Keystore AES-GCM.
- The access sequence advances through `15 → 32 → 51 → 70 → 88 → 93`, displays one diagnostic line with punctuation frames, holds below 100% while the real provider is pending, and reaches 100% only after successful verification.
- Successful access goes to Floating Control. Splash only runs when the user selects **Open game / continue playing**. Home mounts after the splash curtain finishes.

## Floating Control

The Android adapter reads and requests real OS state in the documented order: overlay permission, notifications, background activity/battery exemption, then foreground-service status. The Foreground Service status comes from the service runtime, not from a simulated flag. Bubble/mini-window actions use the native Android service. Browser-preview permission simulation is not part of this APK.

## Home and motion

The initial Home shell retains Dark and White themes, the double torn-paper four-destination dock, the CRT television pull-cord, and the approved Home / Game / Daily Log-in / Settings menu. The pull-cord is drag-only: a tap does nothing; release inside the lower activation zone toggles the dock; recoil and drawer choreography run in parallel. Game navigation remains nested as Home Base → City → World Map.

Anime.js 4.x owns access pacing, screen transitions, splash, pull-cord and dock choreography. CSS owns surfaces and static/reduced-motion presentation. Augusto PXL remains a build-time visual-art authoring/export pipeline; it is not treated as an animation engine and no generated artwork is fabricated for this shell.

## Build

The GitHub Actions workflow builds a debug-signed installable APK and names it using:

`Merzkava-Pocket-v.0.01.003-xxxx.apk`

The debug signing key is generated by the Android build runner. Repository signing secrets are not read by this workflow. This is the Pocket shell build; game-world content, daily reward transactions and production game data integration remain separate workstreams.
